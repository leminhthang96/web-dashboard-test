Two-layer layout: `components/` holds TanStack Table-driven UI (data-table + toolbar + pagination + form dialog + role-assignment dialog) that is stateless and consumes plain `User` / `Role` / `UserRole` types; `services/` owns all persistence. `user-services.ts`, `role-services.ts`, and `user-role-services.ts` use the Firestore client SDK and respect Security Rules. All runtime shape validation lives in `services/types/user-types.ts` using Zod schemas (`userProfileSchema`, `roleSchema`, `userRoleSchema`) plus separate form/payload schemas. Mock fixtures are JSON files under `services/data/` parsed at import time through their corresponding Zod arrays. Seed helpers (`seedUsersWithClient`, `seedRolesWithClient`, `seedUserRolesWithClient`) batch-write fixtures into Firestore for local development. Dependency direction is strictly components → services → types; services never import components.
